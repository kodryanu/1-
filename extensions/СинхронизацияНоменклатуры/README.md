# Расширение "Синхронизация номенклатуры с видами назначений"

Реализовано в расширении конфигурации (префикс имён `Озон_`), без изменения
объектов основной конфигурации, кроме уже добавленного в справочник
"Виды назначений" служебного реквизита `Номенклатура`.

## Что делает

`Catalogs/ВидыНазначений/Ext/ObjectModule.bsl` - расширение модуля объекта
справочника "Виды назначений". При каждой записи вида назначения актуализирует
связанную с ним номенклатуру:

- В номенклатуру переносятся: `Наименование`, `НаименованиеПолное` (из
  одноимённого реквизита вида назначения) и `Категория` (из реквизита
  `КатегорияПоУмолчанию`).
- Если `КатегорияПоУмолчанию` не заполнена - номенклатура не создаётся и не
  трогается; сама запись вида назначения при этом проходит без ограничений.
- Если номенклатура уже была создана раньше, а её текущая категория (её могли
  поменять как непосредственно в номенклатуре, так и переопределить в виде
  назначения) не совпадает с `КатегорияПоУмолчанию` - запись вида назначения
  блокируется (`Отказ = Истина`), пользователю выводится предупреждение с
  просьбой устранить расхождение вручную (в номенклатуре или в виде
  назначения) и повторить запись.
- Группа (папка) для вновь создаваемой номенклатуры берётся из константы
  `Озон_ГруппаНоменклатурыМедицинскиеУслуги`. Если константа не заполнена -
  запись вида назначения также блокируется, с соответствующим предупреждением
  (при обновлении уже существующей номенклатуры группа не проверяется и не
  переустанавливается - см. "Что не делает" ниже).
- Запись/перезапись номенклатуры выполняется в привилегированном режиме -
  реквизит `Номенклатура` служебный, редактирование справочника "Номенклатура"
  напрямую пользователю может быть недоступно.
- Если у уже созданной номенклатуры `Наименование`, `НаименованиеПолное` и
  `Категория` уже совпадают с требуемыми значениями - повторная запись
  номенклатуры не выполняется (лишней перезаписи нет).

## Что не делает (сознательно)

- Не переустанавливает `Родитель` (группу/папку) у уже существующей
  номенклатуры при последующих записях вида назначения - группа из константы
  подставляется только при первом создании номенклатуры. Дальнейшее ручное
  перемещение номенклатуры по группам расширение не отменяет.
- Не снимает связь и не удаляет номенклатуру, если `КатегорияПоУмолчанию`
  впоследствии очистили у вида назначения, к которому номенклатура уже
  привязана - реквизит `Номенклатура` в этом случае просто перестаёт
  обновляться.

## Код

- `Catalogs/ВидыНазначений/Ext/ObjectModule.bsl` - вся логика актуализации
  (`&Перед("ПередЗаписью")`).

## Что нужно сделать в Конфигураторе

Справочник `ВидыНазначений` уже содержит служебный реквизит `Номенклатура`
(тип `СправочникСсылка.Номенклатура`, недоступен для редактирования
пользователем в форме) и реквизиты `НаименованиеПолное` (Строка) и
`КатегорияПоУмолчанию` (тот же тип, что и реквизит `Категория` справочника
"Номенклатура"). Константа `Озон_ГруппаНоменклатурыМедицинскиеУслуги` (тип
`СправочникСсылка.Номенклатура`, ссылка на группу) также предполагается уже
существующей.

1. В дереве расширения откройте
   `Справочники.ВидыНазначений → Ext/ObjectModule.bsl` (справочник будет
   предложено заимствовать - подтвердите). Откройте модуль объекта (не модуль
   менеджера) и вставьте содержимое
   `Catalogs/ВидыНазначений/Ext/ObjectModule.bsl`.
2. Сохраните расширение, обновите конфигурацию базы данных.

## Проверка

1. Создать вид назначения, заполнить `Наименование`, `НаименованиеПолное`, не
   заполнять `КатегорияПоУмолчанию` - записать. Номенклатура не должна
   создаться.
2. Заполнить `КатегорияПоУмолчанию` и записать (при незаполненной константе
   `Озон_ГруппаНоменклатурыМедицинскиеУслуги`) - запись должна быть заблокирована
   с предупреждением про константу.
3. Заполнить константу, повторить запись - должна создаться номенклатура с
   нужными Наименованием/НаименованиемПолным/Категорией, в группе из константы.
4. Изменить `Наименование` вида назначения и записать - номенклатура должна
   обновиться.
5. Записать вид назначения без изменений - убедиться (например, по времени
   изменения в номенклатуре), что повторной записи номенклатуры не произошло.
6. Изменить категорию непосредственно в номенклатуре (либо изменить
   `КатегорияПоУмолчанию` в виде назначения так, чтобы она разошлась с
   номенклатурой) и попытаться записать вид назначения - запись должна
   блокироваться с предупреждением о несовпадении категорий.
