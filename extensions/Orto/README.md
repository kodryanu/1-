# Расширение "Орто" — пары-партии по резерву и свёртка строк в счёте

УНФ 3.0.12.261, расширение `Орто` (префикс имён `ПП_`). Объекты основной конфигурации
не меняются — только заимствование и перехват методов.

## 1. Кнопка «Создать пары-партии» (вкладка «Пары-партии»)

### Что меняется в структуре (Конфигуратор, расширение Орто)

Форма `Документ.ЗаказПокупателя.ФормаДокумента` уже заимствована.

1. **Команды формы** → добавить команду:
   - Имя: `ПП_СоздатьПарыПартии`
   - Заголовок: `Создать пары-партии`
   - Подсказка: `Разбить строки с пустой партией: количество "В резерве" остаётся в строке, на остальное создаются пары-партии по 1 шт.`
   - Действие: `ПП_СоздатьПарыПартии` (процедура уже есть в модуле формы).
2. **Элементы формы** → перетащить команду в командную панель таблицы `Запасы`
   (группа `ЗапасыКоманднаяПанельКоманды`; при использовании упрощённой панели —
   также в `ЗапасыКоманднаяПанельУпрощенно`).

Новых реквизитов не требуется: используются типовые `Запасы.Резерв` («В резерве»),
`Запасы.Партия` и реквизиты справочника `ПартииНоменклатуры` расширения
(`НомерПары`, `Характеристика`, `ЗаказПокупателя`).

Рекомендуется для реквизита `ПартииНоменклатуры.ЗаказПокупателя` установить
«Индексирование: Индексировать» — по нему выполняется отбор партий заказа.

### Код

`Documents/ЗаказПокупателя/Forms/ФормаДокумента/Ext/Form/Module.bsl`:
- `ПП_СоздатьПарыПартии` — обработчик команды (область `КомандыФормы`);
- область `СозданиеПарПартийПоРезерву` — серверная часть.

### Как работает

Пример: строка «товар, 10 шт., В резерве 8, партия пустая» → после нажатия:
- исходная строка: 8 шт., резерв 8;
- ниже две строки по 1 шт. с партиями «Пара N из M ЗПк … от …».

Итого по заказу 10 шт.: 8 из резерва, 2 в производство.

Правила:
- обрабатываются строки товаров (не разделители, не услуги) текущего варианта КП
  с **пустой** партией и `Количество > Резерв`; строки с партией не трогаются,
  поэтому повторное нажатие безопасно;
- если резерв 0 — сама строка становится первой парой (партия, 1 шт.), остальные пары добавляются ниже;
- незарезервированное количество должно быть целым, иначе выводится сообщение
  на поле «В резерве» этой строки и документ не меняется;
- суммы (`Сумма`, `СуммаНДС`, скидки, вес, объём) делятся на 1 шт. с округлением,
  остаток округления остаётся в исходной строке — сумма заказа не меняется ни на копейку;
  `Всего` пересчитывается из `Сумма`/`СуммаНДС` по флагу «Сумма включает НДС»;
- номер пары — сквозной по номенклатуре+характеристике в заказе: сначала повторно
  используются ранее созданные для заказа партии, которых нет в документе
  (например, после удаления строки), новые получают номера после максимального;
  у пар номенклатуры в наименовании обновляется «из M» (запись только при реальном изменении);
- у номенклатуры без учёта партий включается `ИспользоватьПартии`
  (как в существующей команде «Заполнить пары»);
- после разбиения сбрасывается признак «Скидки рассчитаны» и очищается калькуляция —
  так же, как типовая форма делает при копировании строк.

### Оптимизация (рекомендации ИТС)

- **Один серверный вызов** с клиента на всю операцию.
- **Нет запросов в цикле**: все партии заказа по нужной номенклатуре и список
  номенклатуры без учёта партий читаются одним пакетным запросом; признак «партия уже
  в документе» вычисляется в запросе (`Ссылка В (&ПартииДокумента)`).
  Существующие `ПП_НайтиПартию`/`ПП_ПолучитьПартию` выполняют запрос на каждую пару —
  в новом коде не используются.
- **Нет вложенных циклов по табличной части**: один проход для анализа, поиск
  партий номенклатуры — `НайтиСтроки` по индексированным таблицам значений.
- **Нет разыменования ссылок в цикле**: номер и дата заказа берутся из данных формы
  один раз (старая `ПП_НаименованиеПартии` читала заказ из базы на каждую пару).
- **Все записи в базу — в одной транзакции** (`НачатьТранзакцию` перед `Попытка`,
  `ОтменитьТранзакцию` + журнал регистрации в `Исключение`); данные формы меняются только
  после успешной фиксации — при ошибке документ остаётся без изменений.
- Табличная часть формы не правится построчно: она выгружается в таблицу значений
  (`Объект.Запасы.Выгрузить()`), собирается заново одним проходом (строка резерва, сразу
  за ней пары) и загружается обратно одной операцией (`Загрузить`). Количество, партия и
  суммы новых строк задаются явно, а не через копирование.

## 2. Свёртка строк товаров в печатных формах «Счёт на оплату» и «Заказ покупателя»

Строки одного товара, которые различаются только партией (строка резерва и пары-партии),
печатаются одной строкой с суммарным количеством, суммами, НДС, весом и скидками.
Партия, спецификация, ключ связи и номер строки в сравнение не входят. Строки с разной
ценой, % скидки, ставкой НДС, характеристикой, единицей или содержанием остаются отдельными.
Разделители вариантов КП и строки наборов не сворачиваются. Порядок строк сохраняется.

Логика свёртки — в одном месте: общий модуль расширения `ПП_СверткаСтрокПечати`
(`CommonModules/ПП_СверткаСтрокПечати/Module.bsl`). Сворачиваются только данные
документов `ЗаказПокупателя` (проверка типа `Ссылка`).
Реализовано одним проходом по таблице с поиском по индексированной таблице ключей,
без удаления строк (результат собирается в копию колонок).

### Что меняется в структуре (Конфигуратор, расширение Орто)

1. **Общие модули** → добавить модуль `ПП_СверткаСтрокПечати`: флажок «Сервер»,
   остальные флажки сняты. Текст — из `CommonModules/ПП_СверткаСтрокПечати/Module.bsl`.
2. **Счёт на оплату** — `Обработки.ПечатьСчетНаОплату` (уже заимствована), модуль менеджера,
   обработчик «Перед» для `СформироватьПФ`: тело заменить одной строкой
   `ПП_СверткаСтрокПечати.СвернутьТоварыЗаказовПокупателей(ДанныеОбъектовПечати, "ТаблицаЗапасы", Истина);`
   и удалить функции `ПП_СвернутьСтрокиТоваровСРазнымиПартиями`, `ПП_ЕстьПризнак`,
   `ПП_СуществующиеКолонки` (их код переехал в общий модуль).
   Файл: `DataProcessors/ПечатьСчетНаОплату/Ext/ManagerModule.bsl`.
   Номера строк в счёте перенумеровываются подряд (как было).
3. **Заказ покупателя** — модуль менеджера документа `ЗаказПокупателя`, процедура
   `СформироватьЗаказПокупателя`: «Добавить в расширение» → «Установить обработчик:
   ИзменениеИКонтроль». Конфигуратор скопирует тело процедуры; в него перед строкой
   `// Наборы` (перед вызовом `НаборыСервер.КомпоноватьТабличнуюЧастьПоНаборам(ДанныеДокументов, "ТаблицаЗапасы", ...)`)
   добавить:

   ```bsl
   	#Вставка
   	// Орто: строки одного товара с разными партиями (резерв и пары-партии) - одной строкой.
   	// Номера строк сохраняются: по ним ниже подбираются штрихкоды.
   	ПП_СверткаСтрокПечати.СвернутьТоварыЗаказовПокупателей(ДанныеДокументов, "ТаблицаЗапасы");
   	#КонецВставки
   ```

   Полный текст для сверки — `Documents/ЗаказПокупателя/Ext/ManagerModule.bsl`.
   Номера строк здесь не меняются: по `НомерСтроки` типовой код подбирает штрихкоды,
   а номер на печати форма считает своим счётчиком.

Ограничение: если у строк одного товара указаны разные серийные номера, в печать
попадут серии только первой строки.
