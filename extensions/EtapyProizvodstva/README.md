# Расширение "Этапы производства"

Изменения реализованы полностью в расширении `ЭтапыПроизводства` (префикс имён `Орто_`),
без изменения объектов основной конфигурации.

## Проверка исполнителей по этапам

`Documents/ЗаказНаПроизводство/Ext/ObjectModule.bsl`

В `ОбработкаПроверкиЗаполнения` (`&Перед("ОбработкаПроверкиЗаполнения")`) документа
"Заказ на производство" проверяется табличная часть "Операции": для каждого этапа
исполнитель должен быть одинаковым во всех строках этого этапа. **Пустой исполнитель
считается отдельным значением наравне с заполненным** — если для одного этапа в
одной строке исполнитель не указан, а в другой указан, это тоже расхождение и тоже
блокирует запись/проведение. Если для одного этапа встречаются разные исполнители —
запись/проведение блокируется (`Отказ = Истина`), пользователю выводится сообщение
с указанием этапа и всех найденных разных исполнителей (пустое значение — как
"<не указан>"), привязанное к каждой проблемной строке табличной части (чтобы было
видно прямо в форме).

`ОбработкаПроверкиЗаполнения` — единая, рекомендуемая точка для всех проверок
заполнения (срабатывает и при интерактивной записи/проведении, и при программном
вызове `ПроверитьЗаполнение()`), поэтому все подобные проверки в расширении
собираются здесь, а не разбросаны по `ПередЗаписью`/`ОбработкаПроведения`.
`&Перед` (а не `&Вместо`) достаточно, поскольку штатная `ОбработкаПроверкиЗаполнения`
в конфигурациях 1С по стандарту разработки проверяет `Отказ` в самом начале —
это официально рекомендуемый для расширений способ добавить проверку, не
дублируя и не рискуя разойтись со штатной логикой.

## Что делает кнопка "Перемещение (материалы для раскроя)"

В форме списка документов "Заказ на производство" (и в форме самого документа,
для единообразия) появляется кнопка **"Перемещение (материалы для раскроя)"**
рядом с существующей кнопкой "Производство (частичный выпуск)". Пользователь
выделяет один или несколько заказов на производство и нажимает её.

Расширение:
1. Отбирает из табличной части "Запасы" выбранных заказов только строки, у которых
   `Этап.Наименование = "Раскрой деталей"`.
2. Сворачивает отобранные строки по Номенклатура + Характеристика + Партия +
   ЕдиницаИзмерения, суммируя Количество.
3. Открывает **новый (незаписанный) документ "Перемещение запасов"**, табличная часть
   "Запасы" которого заполнена свёрнутыми материалами.
4. В поле "Комментарий" перечисляет через запятую номера исходных заказов на
   производство.
5. Если все выбранные заказы на производство созданы на основании одного и того же
   документа "Заказ покупателя" (реквизит шапки `ЗаказНаПроизводство.ЗаказПокупателя`),
   то этот документ подставляется в поле "Основание" (`ПеремещениеЗапасов.ДокументОснование`).

Документ не проводится и не записывается автоматически — пользователь проверяет
и дозаполняет обязательные поля (склад-отправитель/получатель и т.д.) и сохраняет сам,
как и при обычном создании на основании.

## Почему кнопка добавляется программно, а не декларативно

Первая версия расширения пыталась добавить кнопку "штатным" способом — через
объект метаданных `Команда` с `Группа = "КоманднаяПанельФормыСоздатьНаОсновании"`.
На практике на этой конкретной форме (сильно кастомизированная форма УНФ) это
не сработало: ни автоматическое размещение по `Группа`, ни отметка "видимость"
в Командном интерфейсе формы не приводили к появлению кнопки в рабочем
приложении — даже при отключённых остальных расширениях конфигурации и полных
правах пользователя. Форма списка использует БСП `ПодключаемыеКоманды`
(`ПодключаемыеКоманды.ПриСозданииНаСервере(ЭтотОбъект)` в `ПриСозданииНаСервере`),
но переопределяемый модуль `СозданиеНаОснованииПереопределяемый.ПередДобавлениемКомандСозданияНаОсновании`
в этой базе явно включает динамическую обработку команд создания на основании
только для документа "Заказ покупателя" и справочника "Сотрудники" — для
"Заказа на производство" она не выполняется, а откуда фактически берётся кнопка
"Производство (частичный выпуск)" (`ЧастичныйВыпуск`), однозначно установить не
удалось.

Поэтому кнопка добавляется **программно**, кодом в модуле формы — точно тем же
приёмом, что уже используется в этой же форме для кнопок изменения состояния
заказа (см. `ОбновитьКомандыИзмененияСостояний` в модуле формы списка основной
конфигурации): `Команды.Добавить(...)` + `Элементы.Добавить(..., Тип("КнопкаФормы"), Родитель)`.
Это не зависит ни от деклараций метаданных, ни от других расширений, ни от
особенностей конкретной подсистемы создания на основании — работает всегда,
пока в форме есть элемент `ЧастичныйВыпуск`, рядом с которым размещается кнопка.

## Код

- `CommonModules/Орто_ПеремещениеРаскройСервер/Module.bsl` — серверная логика отбора,
  свёртки и подготовки структуры `ЗначенияЗаполнения` (без изменений с первой версии).
- `Documents/ЗаказНаПроизводство/Forms/ФормаСписка/Ext/Form/Module.bsl` — расширение
  модуля формы списка: программно добавляет команду и кнопку, обрабатывает нажатие
  (берёт `Элементы.Список.ВыделенныеСтроки`).
- `Documents/ЗаказНаПроизводство/Forms/ФормаДокумента/Ext/Form/Module.bsl` — то же
  самое для формы документа (действует на текущий записанный документ).

## Что нужно сделать в Конфигураторе (в расширении "ЭтапыПроизводства")

### 1. Общий модуль

`Общие модули.Орто_ПеремещениеРаскройСервер`

| Свойство | Значение |
|---|---|
| Имя | `Орто_ПеремещениеРаскройСервер` |
| Сервер | Истина |
| Вызов сервера (ВызовСервера) | Истина |
| Клиент (управляемое приложение) | Ложь |
| Клиент (обычное приложение) | Ложь |
| Внешнее соединение | Ложь |
| Привилегированный режим | Ложь |
| Повторное использование возвращаемых значений | Не использовать |

Текст модуля — из `CommonModules/Орто_ПеремещениеРаскройСервер/Module.bsl`.

### 2. Расширить формы (без добавления объекта "Команда")

Объект метаданных `Команда` создавать **не нужно** — вся логика (и команда формы,
и кнопка) создаётся программно кодом модуля формы.

1. В дереве расширения "ЭтапыПроизводства" откройте
   `Документы.ЗаказНаПроизводство → Формы → ФормаСписка`. Форма пока только
   заимствована — платформа предложит добавить её в расширение, подтвердите.
   Откройте модуль формы (не конструктор элементов) и вставьте туда содержимое
   `Documents/ЗаказНаПроизводство/Forms/ФормаСписка/Ext/Form/Module.bsl`.
2. Аналогично для `Документы.ЗаказНаПроизводство → Формы → ФормаДокумента` —
   содержимое `Documents/ЗаказНаПроизводство/Forms/ФормаДокумента/Ext/Form/Module.bsl`.
3. Сохраните обе формы, обновите конфигурацию базы данных, перезапустите клиент.

Код в `&После("ПриСозданииНаСервере")` ищет на форме элемент `ЧастичныйВыпуск`
(если его там нет — процедура тихо ничего не делает, ошибки не будет) и
добавляет рядом с ним, в тот же родительский контейнер, новую кнопку с командой
`Орто_ПеремещениеРаскрой`. Обработчик команды (`&НаКлиенте Процедура
Орто_ПеремещениеРаскрой(Команда)`) объявлен тут же, в модуле формы — платформа
находит его по имени через `Команда.Действие`.

### 3. Расширить модуль объекта документа (проверка исполнителей)

`Документы.ЗаказНаПроизводство → Ext/ObjectModule.bsl`

Документ уже заимствован в расширении. Откройте его модуль объекта (не модуль
менеджера — это разные модули) и вставьте содержимое
`Documents/ЗаказНаПроизводство/Ext/ObjectModule.bsl`. Объектов метаданных
создавать не нужно, это чистый код модуля.

## Проверка

1. Открыть список "Заказы на производство".
2. Выделить несколько заказов, у части табличной части "Запасы" которых есть строки
   с этапом "Раскрой деталей".
3. Нажать кнопку "Перемещение (материалы для раскроя)" (рядом с "Производство
   (частичный выпуск)").
4. Убедиться, что открылся новый документ "Перемещение запасов": в "Запасы" — только
   материалы этапа "Раскрой деталей", свёрнутые и просуммированные; в "Комментарии" —
   номера заказов через запятую; в "Основании" — заказ покупателя (если он один на все
   выбранные заказы).

Проверка исполнителей:
1. В "Заказе на производство" в табличной части "Операции" заполнить две (и более)
   строки с одинаковым Этапом, но разными Исполнителями.
2. Попытаться провести документ — должно появиться сообщение с перечислением этапа
   и разных исполнителей, проведение должно быть заблокировано.
3. Исправить исполнителей на одинаковое значение для этого этапа — документ должен
   провестись без ошибок.
4. Отдельно проверить пустой vs заполненный: для одного этапа в одной строке
   оставить Исполнителя пустым, в другой — заполнить. Проведение тоже должно
   блокироваться (сообщение покажет "<не указан>" среди значений).
